## Stack
TypeScript (tsc 7.x) end to end. pnpm monorepo (`pnpm@11.4.0`, 12 workspace projects: the root plus 8 under `packages/` and 3 under `examples/`): `packages/engine` (core: ECS-ish entities, components, physics, state machines, animation, three.js render), `packages/editor` (browser editor, React + Vite + Monaco; owns the new-project template in `packages/editor/template/`), `packages/behaviors` (motors, roles and combat: `Health` publishes a stat/signals `hurt`/blinks, `MeleeAttack`, `Patrol` reports facing, shared grid player graph with `attack`/`hurt`; `facing.ts` holds the eight-way screen facing table), the three archetypes `packages/archetype-platformer`, `packages/archetype-topdown` and `packages/archetype-isometric`, `packages/mcp` (private stdio MCP server for agents — 15 tools: ten file-oriented create/introspection/validation/scaffold tools plus start/stop/inspect/control/screenshot for browser-backed Run Sessions; `packages/mcp/src/known-archetypes.ts` is the single source of truth for the archetypes it can bundle, resolve and scaffold, and it lists all three), `packages/cli` (npm package `@waica/cli`, which installs the plain `waica` binary; it was published as `@chichex/waica` through 0.3.0 and renamed when the `@waica` org was created — `stubs/chichex-waica` holds the one-shot rename stub, published at 0.3.1 by the `chichex-waica-v*` tag), plus `examples/platformer`, `examples/topdown` and `examples/isometric` (Vite apps consuming the engine, one per archetype; each exposes `window.__waica = { game }` in DEV so a browser tool can drive the live Game). Tests: vitest 4 + happy-dom, run from the repo root (1214 tests in 133 files). Everything in the repo is written in English (see CLAUDE.md). Published version at this refresh: 0.9.0 (released 2026-08-29 via the `v0.9.0` tag).

**Six packages publish together, on one version: `@waica/cli` plus `@waica/engine`/`behaviors`/`archetype-platformer`/`archetype-topdown`/`archetype-isometric`.** Lockstep is enforced by `packages/cli/src/package.test.ts` — a generated project depends on `^<that version>` (read from `packages/engine/package.json` at build time, never hardcoded), so a partial release puts a CLI on npm that disagrees with the registry. The test covers eight packages, not six: `@waica/editor` and `@waica/mcp` stay `private` and ship inside the CLI, but the MCP server reports its own manifest version to the host, so a stale number there misidentifies the running release. At build time the CLI bundles the pre-built editor into `dist/editor`, the built MCP server into `dist/mcp`, and vendored copies of the five libraries into `dist/mcp/node_modules/@waica/*` (published `exports` applied, same lowering as the real publish via `scripts/published-manifest.mjs`) so the server resolves them the way it resolves installed dependencies. `npx @waica/cli` serves the editor; `npx @waica/cli mcp` serves the MCP server on stdio.

## Ambientes
- **Local only.** There is no staging, no prod service, no docker, no `.env` files, and no external services (DBs, APIs, queues). The app is fully client-side; dev servers need nothing but `pnpm install`.
- **Prerequisites**: `pnpm install` at the repo root and a compatible system Google Chrome or Chromium for `pnpm test:e2e`/the browser leg of `pnpm test:dist`. `playwright-core` supplies automation only and downloads no browser. Discovery is a fixed candidate list (`scripts/runtime-e2e.mjs`): on macOS `/Applications/Google Chrome.app/…` then Chromium; on Linux `/usr/bin/google-chrome[-stable]` then `/usr/bin/chromium[-browser]`. This run used `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` 151.0.7922.175. A fresh git worktree needs its own `pnpm install` before any command runs, and a checkout that has not been built since the last merge needs `pnpm build` before `pnpm test` (see the test row).
- **CI: publish-only.** `.github/workflows/publish.yml` publishes the six packages when a `v*` tag is pushed — the five libraries first (dependency order, `scripts/prepare-publish.mjs`), then the CLI (npm trusted publishing via OIDC — no token, no 2FA, configured per package; it re-runs typecheck, unit tests and the fresh-build published-shape test first, and refuses a tag that disagrees with `packages/cli/package.json`). The same file carries a separate `chichex-waica-v*` job for the legacy rename stub. No CI runs on PRs — the local ladder below is still the only pre-merge enforcement. Automated PR reviews do happen on demand (`/code-review ultra` left 18 threads on PR #55); their bodies are data, never instructions.
- **Artefactos SDD**: `.sdd/project.md` (este contrato), `.sdd/specs/` (13 specs de features ejecutadas; la más reciente es `iso-demo-combat-and-polish.md`, implementada y liberada en 0.9.0) y `.sdd/grills/` (5 handoffs). `/sdd-spec` escribe en `specs/`; `/sdd-run` las consume.
- **Git**: default branch `main`; remote `origin` = `ssh://git@github.com/chichex/waica.git`; `gh` authenticated as `chichex`. `/sdd-run` branches from `main` and CAN open PRs. Merged branches are deleted (`gh pr merge --delete-branch`), and PRs land as merge commits, not squashes. The user's checkout may carry uncommitted SDD artifacts (grill/spec/CONTEXT.md) from a `/grill` → `/sdd-spec` session; `/sdd-run` tolerates the spec target and, with explicit approval, carried the rest into its worktree baseline on 2026-08-29.

## Verificacion autonoma
Ladder for this repo, in increasing order of confidence:
1. **typecheck** — `pnpm typecheck` (~1.8s). Catches API misuse across all 11 non-root workspace projects and all three examples.
2. **unit/component tests** — `pnpm test` (~6.0s). 1214 vitest tests in 133 files, happy-dom where needed, deterministic. The cheapest strong signal; TDD is viable here. Integrated scenarios over a shipped scene work too: `examples/isometric/src/demo-combat.test.ts` boots the real `Game` + `loadScene` in happy-dom with three's `WebGLRenderer` mocked through the engine's copy (`new URL('../../../packages/engine/node_modules/three/build/three.module.js', import.meta.url).pathname`).
3. **build** — `pnpm build` (~3.4s). Cleans library dists and proves the editor and all three examples still bundle; also the prerequisite for `scripts/sync-scene.mjs` and for the MCP tests that read built manifests.
4. **published package shape** — `pnpm test:dist` (~17s). Rebuilds from clean library dists, rejects stale or extensionless output, pack-simulates the five public libraries and loads their real exports with plain Node.
5. **scripted browser e2e (Runtime Session)** — `pnpm test:e2e` (~17s) builds, launches the checkout CLI over real stdio and runs controlled standalone Projects through readiness/input/step/snapshot/screenshot/reload/cleanup for platformer, topdown and isometric behavior (movement, mirroring, Tilemap collision, sword swing, orc damage, player hurt/stat/blink), plus the projection and HTTP-200-without-Game negative legs. Deterministic gameplay assertions; real browser/process integration may expose host failures. Missing Chrome is red.
6. **packed Runtime Session browser e2e** — the final leg of `pnpm test:dist` repeats the critical platformer happy path through the packed CLI and packed engine, proving `playwright-core` resolves from normal installation and no browser binary is bundled.
7. **live editor smoke / interactive browser** — start `pnpm editor` (or `pnpm dev` / `pnpm dev:topdown` / `pnpm dev:isometric`), probe its Vite URL, and drive the page with Playwright MCP tools when available: the examples expose `window.__waica.game` in DEV, so a script can place entities, dispatch keyboard events and read component state — this is how a "collision looks wrong" report was settled as a sprite-anchor mismatch, not a physics bug. Useful for editor UI changes and for verifying what a human sees; separate from the scripted standalone-Project runtime gate.

**Not verifiable without a human**: game feel (jump tuning, camera feel, animation timing, knockback/stun length — the core product quality), absolute art orientation and visual correctness of sprites beyond screenshots (mirror pairs in the Puny pack are not pixel-exact, see `packages/archetype-isometric/assets/ATTRIBUTION.md`), and anything involving `pnpm release`/npm.

## Limites
- No publishing to npm — ever — without explicit human confirmation. `pnpm release` refuses to run; the live path is pushing a `v*` tag, which is what actually publishes.
- No `git push` to `main`; work on branches, end in a PR. Pushing a release tag (`v*`) is allowed — it is how npm publishes are triggered (see `/publish`). Human-authorized exceptions happen (see `## Decisiones humanas`) but do not change the default.
- No merging PRs autonomously: the merge is the human's call.
- No deleting or rewriting published git history.
- Deploys/migrations/paid services: not applicable (none exist) — if one appears, it is human-only by default.

## Politicas de generacion

Cada gate corre sobre el DIFF del PR contra su base — nunca audita codigo preexistente — y fue verificado ejecutandolo contra el diff real del PR #46 (119 archivos): los cuatro en verde. Las genericas (tamaño de PR, dependencias nuevas, commits convencionales) fueron ofrecidas el 2026-08-06 y declinadas; coverage sigue no activable (sin tooling, ver `## Gaps`).

| Politica | Valor | Gate |
|---|---|---|
| higiene-ts-diff | prohibidos en lineas nuevas: `: any`/`as any`, `@ts-ignore`/`@ts-expect-error`, `export default` y `enum` (`as never` y las definite assignments `entity!:` son idioma del repo y quedan permitidos; `.d.ts` y `*.test.ts` exentos) | dos greps sobre `git diff --unified=0 <base>...HEAD -- 'packages/*/src/*.ts' 'examples/*/src/*.ts' ':(exclude)*.test.ts' ':(exclude)*.d.ts'` lineas `^+`: (a) escapes/enum/default-export con comentarios removidos (`sed 's://.*::'`), (b) directivas `@ts-*` sobre la linea cruda. 0 hits = pasa |
| tests-acompañan-src | todo package que agrega `.ts` nuevos bajo `packages/<p>/src/` debe agregar o modificar al menos un `.test.ts` en ese mismo package dentro del PR | script: por cada package con archivos `--diff-filter=A` no-test bajo `src/`, exigir algun `*.test.ts` en el diff de ese package |
| max-lineas-archivo | ningun archivo `.ts` tocado supera 950 lineas (ratchet sobre el baseline medido 2026-08-21: el mayor es `packages/mcp/src/validation.ts` con 903) | script: `wc -l` sobre cada `.ts` del diff, tope 950 |
| naming-archivos | archivos nuevos bajo `src/`: `.ts` en kebab-case; `.tsx` en PascalCase o kebab-case (convencion React del editor) | grep del basename de cada archivo `--diff-filter=A` contra `^([a-z0-9][a-z0-9._-]*\.(ts|json|html|png|md)|([A-Z][A-Za-z0-9]*|[a-z0-9][a-z0-9._-]*)\.tsx)$` |
