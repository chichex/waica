## Contexto
The repo is about to grow its third archetype (`@waica/archetype-isometric` — Spec 2 of the partition fixed by the grill, decision 10). This is Spec 1: the engine and editor generalizations the isometric genre needs, with **zero observable behavior change for the platformer and topdown archetypes** (handoff constraint, same criterion as the two previous foundations efforts). The projection fork was closed by the spike (`spike/iso-projection`, `examples/iso-spike/REPORT.md`) in favor of **logical world coordinates projected at render time** (ADR-0009), and maps become **one generic engine primitive** (ADR-0008). Both ADRs are respected, not rediscussed.

What the code does today, at the seams this spec opens:
- `Entity.position` IS `node.position` — the same `THREE.Vector3` (`packages/engine/src/entity.ts:23-25`). Everything reads it: motors (`packages/behaviors/src/topdown-motor.ts:96-103`), `resolveSolidAxis` (`packages/engine/src/solid-axis.ts:43`), `DynamicBody` (`packages/engine/src/components/dynamic-body.ts`), `Solid.bounds` (`packages/engine/src/components/solid.ts:30-38`), the Hitbox dispatch and the camera follow (`packages/engine/src/game.ts:362-417`), the y-sort pass keyed on `entity.position.y` (`game.ts:288-300`), the Runtime Snapshot transform (`packages/engine/src/runtime-inspection.ts:300-303`) and the editor (`packages/editor/src/editor/Viewport.tsx`: `toWorld` axis-aligned unproject at ~604, `pickAt` AABB on `entity.position` at ~617, drags writing `position.set(x, y, 0)`).
- Scene JSON v3 stores `position: [number, number]` and an optional `render: { sort: 'y' }` block (`packages/engine/src/scene.ts:44-61`); `loadScene` adopts the render block BEFORE spawning (`scene.ts:158-166`).
- No tilemap exists at any level: tiles are `Sprite + Solid` entities (topdown placed ~30 by hand, `packages/archetype-topdown/src/scene-default.ts`). Solids are collected per entity with `entity.get(Solid)` in two places (`solid-axis.ts:44-47`, `dynamic-body.ts:229-234`).
- `Sprite` anchors its quad at the center (`packages/engine/src/components/sprite.ts:116`); `AnimatedSprite` centers the full-size quad and keeps shrunk frames bottom-anchored (`animated-sprite.ts:194-206`); topdown dodged pivots with `offsetY` (`tiles/tree`, `packages/archetype-topdown/src/prefabs.ts:170-176`).
- The editor grid is square-only with the diamond extension point reserved in writing (`packages/editor/src/editor/grid.ts:3-8`, `packages/editor/src/project/editor-settings.ts:10,49`); the editor HAS session-wide undo/redo (`packages/editor/src/history/history.ts`, `Editor.tsx:192-214, 1057-1120`) — see `## Desviaciones de fuente`.
- Three generators emit project scenes from the manifests and must stay byte-identical: `packages/editor/src/project/template.ts`, `packages/mcp/src/create-project.ts`, `scripts/sync-scene.mjs` (+ `packages/editor/src/project/__snapshots__/template.test.ts.snap`).

Baseline on this worktree (HEAD `4660e1c`, verified 2026-08-22): `pnpm test` 978 tests / 105 files green, `pnpm typecheck` clean.

**Hard constraints (from the handoff + rev-1 + ADRs)**: logical-coordinate authoring for isometric scenes with the engine projecting at render time; no new sort mode (spike finding 1); collision stays axis-aligned in logical space (no slide-along-normal in the solver); flat elevation (one level, scene format unchanged); the tilemap is generic (square lattice is the degenerate case) and iso is its first consumer; anchor declared on both sprite classes; editor brush = 1 tile, no layers; zero observable change for platformer and topdown.

## Comportamiento esperado

### Item 1 — Projection seam (engine)
- **CA-1** (ALTA): `SceneRenderJson` gains optional `projection?: 'isometric'`; `Game.setSceneRender` adopts it and exposes it read-only (`game.projection: 'isometric' | null`). A scene without `projection` keeps today's exact behavior: `entity.position === entity.node.position` (same `Vector3`, pinned by a characterization test landed BEFORE the change) and every existing scene/game/render-sort test passes untouched.
- **CA-2** (ALTA): A pure, exported engine module (`packages/engine/src/projection.ts`) implements the fixed 2:1 isometric map `projectIsometric(lx, ly) = { x: lx − ly, y: −(lx + ly) / 2 }` and its exact inverse `unprojectIsometric`. Unit: exact values on the lattice (e.g. (1, 0) → (1, −0.5); (0, 1) → (−1, −0.5); (1, 1) → (0, −1)), round-trip property over random points (|error| < 1e-9), linearity (projection of a sum = sum of projections).
- **CA-3** (ALTA): Under `projection: 'isometric'`, `Entity.position` holds **logical** coordinates in a `Vector3` distinct from `node.position`, and the render pass (`renderSurface`, the same place as the y-sort pass, running in edit mode too) writes `node.position.x/y = project(position)` every frame for every entity, preserving `node.position.z`. `spawnFromJson`/`spawnPrefab` positions are logical; `Entity.scale` is untouched. Entities that exist when `setSceneRender` switches the mode are converted in place (their current coordinates become logical). Unit: load a projected scene with an entity at `[2, 1]`, step → `position` = (2, 1), `node.position` = (1, −1.5); move `position` to (0, 0) → next frame `node.position` = (0, 0).
- **CA-4** (ALTA): Y-sort under projection keys on the **render-space** Y (`node.position.y` after the projection pass, which runs first); in identity scenes that value equals today's key, so the existing y-sort tests (`game.test.ts` "y-sort render mode", `render-sort.test.ts`) stay green untouched. `render.sort` stays the `'y'` literal — no new sort mode (spike finding 1). Unit: logical (0, 0) and (1, 1) sharing a layer: (1, 1) projects lower on screen and renders in front; swapping their logical positions flips the order next frame.
- **CA-5** (ALTA): Simulation is projection-invariant: `Solid` bounds, Hitbox overlap dispatch, `resolveSolidAxis` and `DynamicBody` all operate on `entity.position` (logical). Unit (twin scenario): the same layout — a `DynamicBody` with `vx > 0` and a 1×1 `Solid` ahead, then a second run pushing diagonally along a two-cell wall — produces **identical logical trajectories** (per-frame `position` arrays) with and without `projection: 'isometric'`, including the flush stop at the face and the slide along the wall (spike finding 4).
- **CA-6** (ALTA): Camera under projection: the follow target is the target's **projected** position (also for the initial centering in `setSceneCamera`), the lookahead velocity from `CameraVelocityProvider` is projected as a vector (the map is linear), and `camera.position`/`limits` in the scene JSON are render-space. Unit on `Game` with a stubbed provider: the camera center after N steps equals the identity-scene result fed the projected target and velocity; the golden camera tests from the topdown foundations stay untouched.
- **CA-7** (ALTA): Runtime Snapshot `transform.position` reports **logical** coordinates under projection (format unchanged: no new field). Unit on `RuntimeInspector.snapshot` over a projected scene.

### Item 2 — Generic Tilemap primitive (engine, ADR-0008)
- **CA-8** (ALTA): `Tilemap` component (`packages/engine/src/components/tilemap.ts`, exported from the engine index, `componentName: 'Tilemap'`) with flat authorable props: tileset `texture` (optional; flat `color` when absent, mirroring `Sprite`), `cols`, `rows` + `SheetGridParams` (`gridOffsetX/Y`, `spacingX/Y`, `cellWidth/Height` — the same slicing vocabulary as `AnimatedSprite`, tile index = sheet frame index), `pixelArt`; map `mapWidth`, `mapHeight` (cells), `cellSize` (logical units, default 1), `cells: number[]` (row-major, `-1` = empty, shorter arrays read as empty-padded, longer ones ignored past `mapWidth × mapHeight`), `solidTiles: number[]`, `layer`. Cell `(c, r)` occupies logical `[x0 + c·s, x0 + (c+1)·s] × [y0 + r·s, y0 + (r+1)·s]` with `(x0, y0)` = the entity position. Pure grid helpers (`cellIndex`, `cellAt(logicalX, logicalY)`, `cellBounds`) live in a pure engine module with unit tests; `authoringDefaults(Tilemap)` lists exactly the authorable props (meshes/derived solids are `transient`).
- **CA-9** (ALTA): Rendering: one merged `BufferGeometry` (one quad per non-empty cell, UVs from `sheetCell`) under one material, rebuilt wholesale when `cells` or any tileset/map prop changes (reactive setters like `Sprite`'s). Each quad is centered on the cell's **render-space** center: a `cellSize × cellSize` square in identity scenes; under projection the projected cell center with a `2·cellSize × cellSize` quad (the diamond's bounding box). z = `layer × 0.01` — a flat layer band; the Tilemap is NOT a `YSortParticipant` (tall occluders remain entities). Unit (happy-dom, the `makeGame` mold): a 2×1 map with one empty cell yields 4 vertices with exact positions in both modes; UVs of tile index k match `sheetCell`; z pinned.
- **CA-10** (ALTA): Collision through derived Solids: a new engine seam `SolidSource { solids(): readonly Solid[] }` (+ `isSolidSource`) and one shared collector `sceneSolids(game, except)` used by BOTH `resolveSolidAxis` and `DynamicBody` — for scenes without sources it returns exactly today's list in today's order (one `Solid` per entity via `entity.get(Solid)`, entity order; pinned). `Tilemap` implements it: one derived `Solid` per cell whose tile ∈ `solidTiles`, owned by the tilemap (not in `entity.components`), `entity` = the tilemap's entity and `offsetX/offsetY` = the cell center, so bounds come out in logical space; rebuilt on change. Unit: a `DynamicBody` walking +x into a solid cell stops flush at the cell face; pushing diagonally along two adjacent solid cells slides along them (axis-aligned boxes, the case the spike proved clean); `SolidContact.entity` is the tilemap's entity; existing `solid-axis.test.ts`/`dynamic-body.test.ts` untouched.
- **CA-11** (ALTA): Tooling reach: a scene entity carrying an inline `Tilemap` loads via `loadScene` (`resolveProps` resolves `texture`). **Topdown opts in** (human decision 2026-08-22, inference 12): `TOPDOWN_REGISTRY` registers `Tilemap` — the one sanctioned observable change for topdown in this spec — so a topdown project lists it in `list_components`/"+ component" and the editor brush is reachable there without any project-owned re-export; its "exactly N registered components" pin moves by +1 and the conformance suite stays green (it only checks prefab ↔ registry coherence). `PLATFORMER_REGISTRY`, `KNOWN_ARCHETYPES` and `validation.ts` are unchanged; topdown's existing tile entities are NOT migrated. Unit on `loadScene`, the updated topdown pin, the untouched platformer pin.

### Item 3 — Declared anchor on `Sprite`/`AnimatedSprite` (engine + editor)
- **CA-12** (ALTA): Both sprite classes gain `anchorX`, `anchorY` ∈ [0, 1] (default 0.5/0.5 = today's center), declarable in prefab/scene JSON and exposed as `params` (min 0, max 1, step 0.25). Placement is one pure engine function (`spritePlacement({ width, height, offsetX, offsetY, anchorX, anchorY, flipX, frameScaleX, frameScaleY })` → quad `{ x, y, scaleX, scaleY }`) used by both classes: the full-size box is placed so that its anchor point lands on `(offsetX, offsetY)` relative to the entity; `AnimatedSprite`'s variable-size frames keep their feet on the box's floor (today's rule); `flipX` mirrors the box about the entity's vertical axis. **Golden tests landed BEFORE the refactor** reproduce today's exact `mesh.position`/`scale` at the default anchor for: `Sprite` with offsets; `AnimatedSprite` with offsets; a shrunk frame; a flipped sprite with `offsetX` (the existing `animated-sprite.test.ts` pin stays untouched). Then: `anchorY: 0` puts the quad's bottom edge on the entity; `anchorY: 0.25` with `height: 2` reproduces topdown's tree placement without `offsetY`.
- **CA-13** (ALTA): The anchor does not shift the y-sort key (entity Y — twin of topdown CA-4), and `anchorX/anchorY` survive the Sprite ↔ AnimatedSprite swap (`SHARED_APPEARANCE_PROPS`, `packages/editor/src/project/chassis.ts`). Unit on `ySortZ` inputs and `toggleAnimated`.
- **CA-14** (ALTA): Editor appearance gizmo and picking bounds derive from the same placement (a pure helper shared with `boxCenter`/`entityBounds`), so an anchored sprite's amber outline sits on its quad. The topdown `tiles/tree` prefab keeps `offsetY: 0.5` — no migration (its `prefabs.test.ts` pin stays green). Unit on the pure helper.

### Item 4 — Editor: diamond grid, projected picking/gizmos, Tilemap card and brush
- **CA-15** (ALTA): `GridType` gains `'isometric'` (`parseEditorSettings` accepts it, serialize round-trips; square defaults unchanged). For `type: 'isometric'`, `snapPoint` snaps to the projected logical lattice (unproject → round to `size` → project: coupled axes) and `gridLineVertices` emits the two diagonal families — the logical lines `x = k·size` and `y = k·size` over the logical cover of the unprojected rect's bounding box — projected; `gridCoverKey` stays stable across sub-cell pans. The square case is byte-identical (existing `grid.test.ts` untouched). Unit twins of `grid.test.ts`.
- **CA-16** (ALTA logic / MEDIA wiring): The scene viewport's effective grid is a pure `effectiveGrid(scene, settings)`: `render.projection === 'isometric'` forces `'isometric'`, otherwise the editor setting; `size` always comes from settings (logical units). `SceneInspector` gains an "Isometric projection" toggle next to the y-sort toggle, backed by the existing `ops.setRenderProp(scene, 'projection', 'isometric' | undefined)` (stamps v3, drops an emptied block) and committed as a structural change (the live game is recreated). Unit: `effectiveGrid`, `ops` extension, static-render test of the toggle (`scene-render-inspector.test.ts` mold).
- **CA-17** (ALTA logic / MEDIA wiring): Viewport space rule under projection, implemented in a pure module (`packages/editor/src/editor/viewport-space.ts`): every pointer interaction that edits a **logical** quantity (entity drag/drop position, marquee containment, collision box offset/size/polygon points) converts the pointer through the inverse projection; **render-space** quantities (appearance box, camera frame/marker/limits) stay in screen space; picking tests the pointer against the entity's **projected** position with its render bounds; selection/multi gizmos draw at projected positions and collision outlines (`Solid`/`Hitbox`/`DynamicBody`) draw their vertices projected (a logical rect reads as a diamond). Unit: dropping at screen (1, −1.5) in a projected scene commits logical `[2, 1]`; the pick at that screen point hits the entity; identity scenes produce today's values (existing `box-math.test.ts` untouched). - **CA-18** (ALTA logic / MEDIA UI): Tilemap inspector card: a dedicated card (not the generic behaviour card) showing map size, cell size, layer, solid tiles, the tileset (texture via the existing art picker + `cols`/`rows`/slicing) and a **tile picker** rendering the tileset's cells to choose the brush tile, plus a **Paint** toggle. `cells` is never rendered as a raw field. Unit: static render (`renderToStaticMarkup` mold) asserts the fields, the picker cell count (= `cols × rows`) and the toggle.
- **CA-19** (ALTA logic / MEDIA UI): Brush: with Paint on and a tile selected, pointer down/drag over the scene viewport paints the cell under the pointer (pointer → logical via CA-17 → `cellAt`); Shift while painting erases (`-1`); pointers outside the map are a no-op (no auto-grow); the live `Tilemap` instance updates during the stroke (the `applyProp` path); pointer-up commits **one** `ops.setComponentProp(scene, name, 'Tilemap', 'cells', next)` per stroke (a prefab-owned Tilemap lands `cells` in the instance `overrides`), which the existing session history records as one undo step — no brush-specific undo code. Unit: pure `paintCell(cells, mapWidth, mapHeight, c, r, tile)` (returns a fresh array or `null` out of bounds) and a stroke reducer; `ops` test on the commit shape. Interaction covered by CA-26.

## Desviaciones de fuente
Conflicts between the handoff and the current code, surfaced rather than silently reinterpreted:
- **D1 — The editor has undo/redo.** The handoff (supuestos) and DESIGN.md say the editor has none and that the brush must be designed assuming its absence. The code has session-wide undo/redo (`packages/editor/src/history/history.ts`; `commit`/`recordBatch`/`doStep` in `Editor.tsx`) recording every scene commit. Consequence taken here: the brush commits one `cells` value per stroke through the regular `commit` path and gets undo for free (CA-19, inference 18); no undo design is needed. DESIGN.md remains stale (pre-existing, not fixed here).
- **D2 — "Diamond as a parameter" vs the logical-world model.** Decision 6 (and ADR-0008's first wording) described the lattice as a square/diamond parameter; rev-1 (which prevails) makes every isometric scene author on a logical square grid projected at render time, so a diamond lattice in logical space has no meaning and an explicit parameter would be a second source of truth. Chosen: derived from the projection (inference 8). **Resolved by the human 2026-08-22**: confirmed, and ADR-0008 was amended to say the diamond is a property of the scene projection, with the `lattice` parameter recorded there as a rejected alternative.
