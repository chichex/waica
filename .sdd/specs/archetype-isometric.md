## Contexto
Spec 1 (`.sdd/specs/iso-engine-foundations.md`, PR #51, merged as `82c4a43`) landed everything the genre needs from the engine and the editor, with zero observable change for the two existing archetypes: the **projection seam** (`render.projection: 'isometric'`, logical `Entity.position` projected into `node.position` every frame by `projectIsometric`/`unprojectIsometric`, ADR-0009), the generic **`Tilemap`** primitive with derived collision through the `SolidSource` seam (ADR-0008), the **declared anchor** (`anchorX`/`anchorY` on both sprite classes, replacing the `offsetY` convention) and the **isometric editor** (diamond grid, projected picking/gizmos, Tilemap card and 1-tile brush). This spec ships the consumer: the third archetype, published as the sixth lockstep package. `packages/archetype-topdown` (~1060 lines of source across 19 files, 6 of them tests) is the mold; `pnpm -r build` orders topologically, so a new package needs no build wiring.

What exists today at the seams this spec consumes:
- `projectIsometric(lx, ly) = { x: lx − ly, y: −(lx + ly) / 2 }` and its exact inverse (`packages/engine/src/projection.ts`). Logical +x runs screen right-and-down, logical +y screen left-and-down; the y-sort keys on the projected Y, so depth is already correct (spike finding 1).
- `Tilemap` (`packages/engine/src/components/tilemap.ts`) draws one merged geometry, one quad per non-empty cell. Under projection each quad is **fixed** at `2·cellSize × cellSize` centered on the projected cell center (`tilemap.ts:298-306`) — a source cell taller than 2:1 would be squashed. It is a `SolidSource` (`SOLID_SOURCE_SYMBOL` opt-in brand) with one derived `Solid` per cell whose tile ∈ `solidTiles`, and it is deliberately **not** a `YSortParticipant`: tall occluders stay entities. It is already registered in `TOPDOWN_REGISTRY_DATA`.
- The directional contract already types eight directions and mirroring (`packages/engine/src/animation/directional.ts:122-135` is a type-only iso fixture with exactly the `w→e`, `nw→ne`, `sw→se` flip fallbacks). **The mirroring path has never run**: topdown only exercises `w→e`, and `DESIGN.md:23` has promised NE→NW since the start.
- `TopDownMotor` (`packages/behaviors/src/topdown-motor.ts`) is the shape to clone: passive toolbox, no `onUpdate`, `run`/`step`/`speed`/`halt`, per-axis `resolveSolidAxis`, both provider seams (`CameraVelocityProvider`, `AnimationFacingProvider`), four-direction facing.
- The archetype registration surface is ~12 touchpoints, measured: `KNOWN_ARCHETYPES` + `loadBundledModule` switch + `FALLBACK_PACKAGES`, editor `ARCHETYPES` + picker card + `script-sources.ts`, conformance `MANIFESTS`, `PUBLISHED_LIBRARIES`, the CLI lockstep list, four points of `test-dist.mjs`, `sync-scene.mjs` `TARGETS` + example + `dev:*`, `/publish` SKILL.md + READMEs. Everything else derives from those lists.
- The art originals are already sourced and resguardados outside the repo: `~/Sync/workspace/waica-art-src/iso-kit-a/` (40 PNG, 1 MB, `SOURCES.md` with URLs, licence quoted per page, layout and sha256). The run recomposes from there **offline** — no network, unlike the topdown run.

Baseline on `main` (HEAD `82c4a43`, verified 2026-08-22): `pnpm test` 1040 tests / 117 files green, `pnpm typecheck` clean. All seven manifests sit at 0.7.0.

**Hard constraints (handoff + rev-1 + rev-2 + ADRs)**: the demo is the same Zelda-like action-adventure as topdown, in isometric — explore, an NPC to `interact` with, real occlusion; flat elevation (one level); the `Tilemap` is the map (iso is its first consumer); five art rows ship (`n/ne/e/se/s`) and `w/nw/sw` mirror at runtime; scenes are authored in logical coordinates; collision stays axis-aligned in logical space; no projectiles, no dialogue system, no melee, no rooms camera.

### Item 2 — Screen-relative movement (`@waica/engine` + `@waica/behaviors`)
- **CA-6** (ALTA): A pure exported engine function `screenInputToLogical(ix, iy)` lands next to `projectIsometric` (`packages/engine/src/projection.ts`), mapping a screen-relative input vector to a logical world direction: `{ x: (ix − iy) / √2, y: (−ix − iy) / √2 }`, then clamped to length 1 (a longer vector is normalized, a shorter one passes through). Unit: `(1, 0)` → a unit vector that projects to pure screen `+x`; `(0, 1)` → a unit vector that projects to pure screen `+y`; the map is **orthogonal** (it preserves lengths and angles, so a fully-pressed input is a unit logical vector in all eight directions — the same tiles-per-second in every direction); `(0, 0)` → `(0, 0)`; a diagonal input `(1, 1)` clamps to length 1 and projects onto a tile axis. It is deliberately NOT `unprojectIsometric` (which is anisotropic and is for points, not input); a test states that difference on one value so nobody "simplifies" the two into one.
- **CA-7** (ALTA): `IsoMotor` in `@waica/behaviors` — the passive toolbox shape of `TopDownMotor`, no `onUpdate` of its own:
  - `run(inputX, inputY, dt)` takes **screen-relative** axes, maps them through `screenInputToLogical`, and damps `vx`/`vy` toward `direction × moveSpeed` with `acceleration`/`deceleration` (same damp call as `TopDownMotor`), no gravity.
  - `facing` is one of the eight declared directions, derived from the **sign pair of the raw screen input** (`(1,0) → 'e'`, `(1,1) → 'ne'`, `(0,1) → 'n'`, `(−1,1) → 'nw'`, `(−1,0) → 'w'`, `(−1,−1) → 'sw'`, `(0,−1) → 's'`, `(1,−1) → 'se'`); a zero input keeps the last facing (topdown's tie rule, generalized). Starts at `'s'` (facing the camera).
  - `step(dt)` integrates and resolves each **logical** axis through the shared `resolveSolidAxis`, so it collides against tilemap-derived Solids and Solid entities alike.
  - Implements `CameraVelocityProvider` returning the **logical** velocity (the engine projects it as a vector — foundations CA-6) and `AnimationFacingProvider` returning `facing`.
  Unit harness in the style of `topdown-motor.test.ts`: flush contact against a Solid, no tunneling at a clamped `dt`, equal logical speed for all eight inputs, deceleration to 0, no gravity, the facing table above including the zero-input hold, and both provider seams. Plus one projection-aware test: with `render.projection: 'isometric'`, holding `right` moves the entity purely right in **render** space while both logical coordinates change.
- **CA-8** (ALTA): `ISO_PLAYER_ROLE` in behaviors (driver `IsoMotor`), cloned from `TOPDOWN_PLAYER_ROLE`: `idle`/`walk` graph with `move`/`stop` signals, the `dead` beat, `interactUpdate` on the `'*'` always-hook, and `isoPlayerUpdate` as the `default`/`idle`/`walk` body update. The `npc`, `patroller` and `chaser` roles are reused unchanged from behaviors (see `## Desviaciones de fuente`, D1). Unit via the state-machine harness: graph consistency, `move`/`stop` edges, death beat, `'*'` hook, and a behavioural update driving a real `IsoMotor`.

## Desviaciones de fuente
Conflicts between the handoffs and the current code, surfaced rather than silently reinterpreted:
- **D1 — "Reusa `Interactable`, roles y bindings" (decisión 3) vs. a new driver.** `Interactable` and the bindings are reused literally. The **player** role cannot be: `TOPDOWN_PLAYER_ROLE` declares `driver: 'TopDownMotor'` and its update calls `TopDownMotor` methods, while isometric movement needs the screen→logical mapping and eight-direction facing. Taken here: a new `ISO_PLAYER_ROLE` that is a clone of topdown's graph (same states, same signals, same `interactUpdate` hook) with `IsoMotor` as the driver; `npc`, `patroller` and `chaser` are reused unchanged. The spirit of the decision (no new interaction system, no new state vocabulary) is preserved.
- **D2 — "Puny a 2× nearest-neighbour" (rev-2, decisión 2).** Both sprite classes and the `Tilemap` filter with `THREE.NearestFilter` when `pixelArt` is on (`sprite.ts:125-127`, `animated-sprite.ts:173-175`, `tilemap.ts:254-256`), so upscaling the PNG 2× and drawing it at the same world size produces a **pixel-identical** frame at four times the file size. The apparent scale rev-2 asked for (a ~32 px body against 64 px diamonds) is obtained by declaring `width/height: 2` on the sprite. **Resolved by the human 2026-08-22**: ship the native 32×32 cells. The rev-2 decision is honoured in intent, not in letter.

- **Art is the highest-variance item, by precedent**: both post-review bugs of the topdown archetype were art, and only the human found them. - **Hand-slicing `big_isometric_tileset64x32.png` is the largest unbounded task in the spec**: one unspaced 1024×1344 sheet with varying cell heights and a "work in progress" label from its author.
