## Hechos comprobados

Verified in this session at `main` (`aa14fc1`, v0.27.0); citations are `file:line` under `packages/editor/src` unless stated.

- **A 3D scene is read-only in the editor.** `isReadOnlyView(game)` is `game.space === '3d'` (`editor/viewport-camera.ts:11-13`); it turns off pointer gestures (`use-viewport-pointer.ts:42`), prefab drop (`use-prefab-drop.ts:21`) and pan/zoom (`viewport-game.ts:73-74, 91, 127`); `viewport-frame-overlays.ts:81-95` hides grid, selection, light and camera gizmos; `Viewport.tsx:111-133` hides `ViewportGridTools` and `ViewportNavTools` through `flat`. Pinned by `viewport-3d.test.tsx:55-116`. ADR 0027 (line 11) and ADR 0028 (line 19) defer picking, gizmos and grid to "a 3D editor block".
- **The viewport embeds the real engine `Game`** on its own canvas, no iframe (`viewport-game.ts:19-60`), with `game.simulate = mode === 'play'`; it is rebuilt per `[epoch, mode]` (`use-viewport-game.ts:308-330`); overlays draw from `game.onUpdate`, which still runs with `simulate` false (`packages/engine/src/game.ts:711-718`). The editor looks through the scene's own perspective camera, the one Play uses (`packages/engine/src/camera-rig.ts:26-36`); scene camera edits are pushed with `game.setSceneCamera` (`use-viewport-game.ts:215-220`). The editor does not use the Runtime Bridge.
- **3D scene camera:** `{ kind: 'perspective', position, target, fov, near, far }`, defaults `[0,5,10]`, `[0,0,0]`, 60, 0.1, 1000 (`packages/engine/src/scene-camera-3d.ts:10-49`).
- **Engine picking exists:** `raycastPick` tests Model roots and falls back to the y=0 ground plane (`packages/engine/src/pointer-raycast.ts:12-59`), called from `pointer.ts:151`. Only Models are hit; lights, the camera and empty entities have no mesh.
- **2D editing model to reuse:** single and multi selection (`use-entity-selection.ts:7-35`); 2D picking `pickEntityAt` (`viewport-pointer-targets.ts:54`), handles and markers (`viewport-gestures.ts:80-110`); shift-click toggle, marquee, drag, box resize, polygon edit (`Viewport.tsx:63-94`); session-wide undo/redo with before/after snapshots, grouping and a 1 s coalesce (`history/history.ts:6-30`); edits through pure `scene/ops.ts` (`moveEntity :343`, `setEntityTransform :366`); 3D transforms are edited only in the Inspector today (`EntityIdentity.tsx:44-45`). Persistence is in-browser through `ProjectFS` (`RealFS` on File System Access, `MemFS`) with debounced writes (`fs/project-fs.ts:11-26`, `use-persistence.ts:26-40`).
- **Keyboard shortcuts** all require Cmd/Ctrl (`Z`, `Y`, `D`, `G`; `editor/use-editor-shortcuts.ts:25-33`): bare `W`, `E`, `R`, `F` are free.
- **three 0.186.1** ships `OrbitControls`, `MapControls` and `TransformControls` in `examples/jsm/controls/` (checked in `node_modules`); nothing in the repo imports them. Only `GLTFLoader` (`assets/model-backend.ts:2`) and `SkeletonUtils` (`assets/model-cache.ts:2`) are used. Vite aliases bare `three` to `three/webgpu` (`packages/editor/vite.config.ts:6-9`, ADR 0027).
- **Clip names are unknown to the editor.** `clipsUnknown` is true for every `Model` with a `src` and `knownClips` returns null then (`editor/inspector/component-meta.ts:86-99`); `Animator.initialClip` is a free-text row (`editor/inspector-animator.test.tsx:23-27`). The state modal's clip field is a select over the sprite's clips (`StateEditorModal.tsx:127-149`); `missing-option.tsx` already renders a stored value that is not among the options.
- **The MCP reads glb clips** with `parseGlbDocument(bytes)` (`packages/mcp/src/glb-document.ts:30-41`), which decodes only the JSON chunk with `TextDecoder` (no Node API), and `clipNamesOf` (`:79`), used by `animator-validation.ts:4-39`. At runtime the names live in `Animator.clipNames` and `ModelHandle.animations`.
- **Inspector rows are schema-driven** from a component's `static params` (`editor/inspector/component-meta.ts:28-46`); `PropRow` renders a select for `options` (`PropRow.tsx:147-165`); `ModelParamRow` lists the project's model art (`param-kind-rows.tsx:50-70`).
- **Tests:** Testing Library on happy-dom, a fake WebGPU renderer through `vi.mock` (`viewport-3d.test.tsx:1-14`), StrictMode mounts. No e2e drives the editor UI: `scripts/runtime-e2e.mjs` only resolves Vite from the editor package (`:2010-2012`).
- **Sizes:** largest editor `.tsx` is `ProjectPane` (417 lines) against the 950 cap; `game.ts` was ~897/950 physical lines at block 3.
- **Design inventory:** `.sdd/project.md` has no `## Diseño` section; the editor's existing floating viewport tools (`ViewportTools.tsx`: `ViewportGridTools`, `ViewportNavTools`) are the reference components.

## Decisiones resueltas

**A. Scope and editor camera**
1. **Everything in one spec**, delivered as stacked PRs like block 3: orbit, picking, gizmos, grid and helpers, clip dropdowns.
2. **The editor has its own perspective camera.** The scene camera is never moved by navigation; it is drawn as a gizmo and Play uses it. No "align scene camera with view" action.
3. **Orbit through three's `OrbitControls`.**
4. **Initial pose = the scene camera's pose** (position and target).
5. **The editor camera pose is remembered per scene in `localStorage`**; not written to the project.
6. **Mouse map:** left selects (and drags gizmos); middle or Alt+left orbits; right or Shift+middle pans; wheel zooms.
7. **`F` frames the selection** (orbit target to its center, distance from its bounding box).

**B. Selection and picking**
8. **Meshless entities (Sun, Point Light, the camera, empty entities) draw clickable icons** that picking recognizes.
9. **Selection is marked by a line bounding box** in the 2D selection color.
10. **Shift+click multi-selection; no marquee in 3D.**
11. **Picking reuses the engine's `raycastPick`**, extended to take the editor camera and the icons; one hit logic for game and editor.

**C. Gizmos and transform**
12. **three's `TransformControls`.**
13. **Modes with `W` / `E` / `R`** plus buttons.
14. **World space by default, with a toggle to local.**
15. **Snapping while Ctrl is held.**
16. **Snap steps are editable in the toolbar** (position, rotation, scale; defaults 0.5 u, 15°, 0.1), persisted in `localStorage`.
17. **With a multi-selection the gizmo transforms the group around its center**, one undo entry.
18. **Prefab drop in 3D lands on the surface under the cursor**, or on the y=0 plane when nothing is hit.

**D. Visual helpers**
19. **Grid on the XZ plane (y=0) with colored X/Z axes**, toggled by the existing grid button.
20. **Helpers drawn in edit mode:** the scene camera's frustum (real fov/near/far), the Sun's direction, the Point Light's range, colliders as wireframes. Sensors share the collider look.
21. **Helpers are always visible in edit mode behind one global toggle**; never in Play.

**E. glb clips**
22. **Clip names come from the glb's JSON chunk**, read through `ProjectFS.readFile`; the model need not be loaded.
23. **The parser is a pure function exported by `@waica/engine`**, imported by the MCP and the editor; it goes in the migration note.
24. **Dropdowns:** `Animator.initialClip`, the keys of `Animator.clips`, each state's clip in the state modal; the missing-clip warnings in the state list come back for Models.
25. **Fallback:** when the clips cannot be read (external URL, broken file) the field stays free text; a stored name absent from the glb shows as a "missing" option (`missing-option.tsx`) and is never dropped.

**Design**
26. **The 3D controls live in a floating viewport overlay**, `ViewportTransformTools` in `ViewportTools.tsx`, beside the existing tools, visible only in 3D edit mode: mode, world/local, snap steps, helpers toggle, frame selection.
27. **Accessibility and platforms:** semantic `<button>`s with `aria-pressed` and the shortcut in the `title` ("Move (W)"); orbit, pan and zoom from the keyboard when the viewport has focus (arrows orbit, Shift+arrows pan, `+`/`-` zoom); `OrbitControls`' touch and trackpad gestures. Mobile and webview are out.

**F. Verification**
28. **Unit tests plus a new `pnpm test:e2e` leg that drives the editor UI** in Chrome: open the editor with the smoke-3d scene in `MemFS`, pick, drag a gizmo, assert the saved JSON, on webgl2 and webgpu.
29. **A human protocol in `pnpm editor` with `examples/smoke-3d`:** orbit/pan/zoom with mouse, trackpad and keyboard; select the Knight, a light and the camera; move/rotate/scale with snap; `F`; prefab drop; the clip dropdowns; reload and find the remembered pose.

## Diseño

- **Surface:** the editor (`packages/editor/src`), no formal design system; `.sdd/project.md` lacks `## Diseño` (`/sdd-init --update` pending). Reference components: `ViewportTools.tsx` (`ViewportGridTools`, `ViewportNavTools`), `PropRow`, `missing-option.tsx`.
- **Screens and flows:** the scene viewport in 3D edit mode (orbit, pick, transform, drop, frame) and in Play (no helpers, no icons, scene camera); the Inspector's Animator rows and the state modal's clip field with glb clips. States: clips readable (dropdown), unreadable (free text), stored name missing (marked option).
- **Reuse vs. new:** new `ViewportTransformTools` beside the existing floating tools, same style; reuse the 2D selection color, the grid button, `missing-option.tsx`, the select of `PropRow` and of `StateEditorModal`.
- **Accessibility:** decision 27. No captures were taken: there is no renderable mock for this surface.

## Handoff

**Topic and scope.** Make scenes with `render.space: '3d'` editable in the editor's viewport: an editor-owned orbit camera, picking with icons for meshless entities, move/rotate/scale gizmos with snapping, a grid and component helpers, and clip dropdowns read from the glb. One spec in stacked PRs. The third-person archetype (block 5) stays out.

**Confirmed decisions.** The twenty-nine above; the spec takes them as confirmed and does not re-ask them.

**Constraints and non-goals**
- No 3D marquee, post-process outline, shader infinite grid, distinct sensor color, "align camera with view", mobile or webview support.
- No orthographic 3D, no 2.5D, no new hierarchy model.
- No new dependency (`OrbitControls` and `TransformControls` ship with three).
- Play, the simulation, the fixed step (ADR 0014), the Component Update Schedule and the 2D editor are untouched; 2D editor tests pass unchanged.

**Explicit assumptions** (the spec lists them as `[ASSUMED]` inferences)
- The `Game` gains a way to render and project through a view camera other than the scene camera while editing; the API name is the spec's call, and ADR 0027's read-only clause is superseded or amended.
- `TransformControls` and `OrbitControls` work with `WebGPURenderer` [inference: they are plain meshes and DOM listeners; the spec opens with a spike on both backends].
- A hit on a child mesh of a glb selects the owning entity; a click on empty space clears the selection; each gizmo drag is one history entry through the existing coalesce.
- Icons and helpers never appear in Play, in Runtime Session snapshots or in screenshots taken by the MCP.
- `raycastPick` on a `SkinnedMesh` hits the posed mesh [inference: three's `SkinnedMesh.raycast` applies bone transforms].
- Minor bump (0.28.0) with a migration note for the new engine export and any `raycastPick`/camera API change.

**Risks and deliberately deferred questions**
- **#151:** CI's Linux WebGPU frame is blank; the new leg's pixel assertions run only where the frame draws, state and JSON assertions on both backends.
- First e2e that drives the editor UI: whether `MemFS` plus the smoke-3d scene loads headless and how the leg reaches the editor (built CLI or Vite) is the spec's call; the e2e wall time grows.
- A box `Collider` does not follow a yaw after its body is created (block 3 risk); the wireframe draws the JSON shape.
- `game.ts` line budget: the view-camera seam may need to live outside it.
- `.sdd/project.md` is stale (Vitest 5, version 0.27.0, no `## Diseño`): `/sdd-init --update` before or alongside the spec.
