## Hechos comprobados

Verified in this session by reading the code at `main` (`926891e`, v0.26.0); citations are `file:line` under `packages/engine/src` unless stated.

- **The clips already reach the runtime and nothing plays them.** `GltfModelBackend` keeps `gltf.animations` (`assets/model-backend.ts:36`); `ModelCache.handle()` returns `ModelHandle { root, animations, settled }` with the root cloned through `SkeletonUtils.clone` and the same `AnimationClip` objects for every consumer (`assets/model-cache.ts:13-17, 79-92`). `Model` takes only `.root` and drops `animations` and `settled` (`components/model.ts:107`); it keeps no handle, mixer or clip list. The README says the clips "are not played yet" (`packages/engine/README.md:250`).
- **`StateMachine` is wired to `AnimatedSprite` by class.** `playClip` does `entity.get(AnimatedSprite)` and calls `sprite.clips`, `sprite.play`, `sprite.setFlipX`, `sprite.current` (`state/state-machine.ts:238-252`); `playDirectionalClip` resolves `<state>-<dir>` through the one installed contract (`:259-271`); `reresolveOnFacingChange` runs at the end of every `onUpdate` (`:287-294`). The facing provider is duck-typed: the first sibling with `getAnimationFacing()` (`:273-277`). Triggers are only `input:`, `timer:` and `signal:` (`:47-63`); there is no clip-end trigger, so a 2D attack ends on a timer (`packages/behaviors/src/grid-player-role.ts:56-58`).
- **The 2D clip contract.** `ClipDef { frames, fps, loop? }`; `play(name)` returns early for the current clip or an unknown name; no `stop`, `playing`, speed, crossfade or end event (`components/animated-sprite.ts:220-226`; `animation/clip-player.ts:3-40`). `AnimatedSprite` declares `updateAfter = ['StateMachine']` (`animated-sprite.ts:30`, ADR 0004).
- **Everything advances per Simulation Step.** `simulateStep` runs `component.onUpdate?.(SIMULATION_STEP)` for every component, then `runSimulationPhases` (physics step, contacts, Hitbox and sensor collisions), then the camera (`game.ts:741-756`; `simulation-phases.ts:13-19`). There is no per-render-frame component hook and no pose interpolation (`component.ts:84-120`).
- **`CharacterMotor` neither rotates the entity nor exposes state** (`packages/behaviors/src/character-motor.ts:40-51`); the state lives on `RigidBody`: `desiredVelocity`, `linearVelocity`, `jump()`, `grounded` (`components/rigid-body.ts:71-88`). A kinematic body has its rotation locked and `syncBodyPose` never writes its rotation, so `entity.node.rotation` is free (`physics-3d/body-sync.ts:127, 181`). A collider's rotation is read from `node.quaternion` only when the body is created (`body-sync.ts:116-117`). `Entity` has no rotation, facing or yaw accessor (`entity.ts`).
- **Who owns facing today.** The five 2D motors and the movers own it: `PlatformerMotor.facing = ±1` written to `entity.scale` every update (`packages/behaviors/src/platformer-motor.ts:70, 94, 102`), `TopDownMotor`/`IsoMotor` set `facing` from input (`topdown-motor.ts:32-34`, `iso-motor.ts:28`), `GridMotor.getAnimationFacing()` (`grid-motor.ts:49-52`), `Patrol` (`patrol.ts:59-65, 84`), `Chaser` (`chaser.ts:67, 94`). Unreal turns the character in `UCharacterMovementComponent` (`bOrientRotationToMovement`, `RotationRate` in deg/s, negative = instant); Unity's `CharacterController` and Godot's `CharacterBody3D` do not rotate, their controller scripts do, and Godot's community rotates the visual mesh, not the body.
- **2D signals come from the role, not the motor.** `player-states.ts` reads the motor and emits `land/move/stop/rise/fall` (`packages/behaviors/src/player-states.ts:66-78`); `Health` emits `hurt` and `death`.
- **No glb in the repo has animations or skins.** `examples/smoke-3d/art/tree.glb` (5852 B) and `packages/engine/fixtures/unit-box.glb` (928 B) are generated by `scripts/generate-smoke-3d-model.mjs` and a fixture script, original MIT work (`examples/smoke-3d/ATTRIBUTION.md`); both have `animations: []`, `skins: []`. The smoke Player is a scaled box primitive with a capsule `Collider`, a kinematic `RigidBody` and `CharacterMotor`.
- **Test infrastructure.** `FakeModelBackend` gives every URL a box mesh plus `[new THREE.AnimationClip('Idle', 1, [])]` (`assets/test-helpers.ts:79-115`); `model-loader.test.ts:70-98` asserts two handles get separate skeletons; a real glb loads in Node through `?inline` and the real `GLTFLoader` (`assets/gltf-model-backend.test.ts:9-42`, `vitest.config.ts:5`). `ready3dGame()` runs real Rapier (`test-game-3d.ts:20-34`).
- **three 0.186.1 through `three/webgpu`** exports `AnimationMixer`, `AnimationClip`, `AnimationAction`, `SkinnedMesh`, `Skeleton`, `LoopOnce`/`LoopRepeat` (`build/three.webgpu.js`); `SkeletonUtils` is already in the MCP's `THREE_SPECIFIERS` and `FALLBACK_SPECIFIERS` (`packages/mcp/src/project-component-fallbacks.ts:99-105`). No new dependency is needed. glTF materials stay plain `MeshStandardMaterial` and the e2e draws them on both backends.
- **MCP and docs.** `missing-clip` is checked for `AnimatedSprite` literally or through the directional contract (`packages/mcp/src/state-machine-validation.ts:121-139`, `clip-resolution.ts:19-29`); `gltf-resource-validation.ts` already reads glb files from the MCP; `component-space-mismatch` reads `static space` (`scene-space.ts:57-61`); `describeComponent` emits `space` and `updateAfter` (`introspection.ts:67-80`). `physics-docs.test.ts` pins ADR title, `CONTEXT.md` glossary entries and README `- **Name.**` bullets. Neither `AnimatedSprite` nor `StateMachine` overrides `inspectState`.
- **e2e and bench.** `scripts/runtime-e2e-smoke-3d.mjs` runs on webgl2 and webgpu, copies `tree.glb` into a demo Project, asserts the glb loaded, snapshot, pixels and physics; on CI's Linux WebGPU it asserts a blank frame (#151). Bench has `animated-sprites-{500,2000}` (2D) and `falling-boxes-{200,1000}` (3D); no skinned scenario.
- **Budget.** `game.ts` 897/950 physical lines, about 598/600 logical; `state/state-machine.ts` 295; `components/model.ts` 133; `assets/model-cache.ts` 152.

## Decisiones resueltas

1. **`Animator` component** (engine, `static space = '3d'`), a sibling of `Model`: it takes the clips of the Model's handle, builds one `AnimationMixer` over the cloned root and exposes `play(clip)` and `current`. `Model` keeps only drawing. `updateAfter: ['StateMachine']`, like `AnimatedSprite`.
2. **Clock: the Simulation Step.** `mixer.update(1/60)` in `onUpdate`; nothing per render frame. Deterministic, visible step by step in Run Sessions and `inspect_runtime`, pose aligned with physics.
3. **The `play(clip)` contract.** `StateMachine` stops importing `AnimatedSprite` and talks to the first sibling that implements the interface (duck-typed, like `getAnimationFacing`); `AnimatedSprite` and `Animator` implement it. 2D behaviour is identical: the existing tests pass unchanged.
4. **A `clip:end` trigger** in the state machine, for 2D and 3D: `AnimatedSprite` reports it when a `loop: false` clip reaches its last frame, `Animator` when a `loop: false` clip finishes. Additive: nothing that ends on a timer today changes.
5. **3D facing is rotation.** `CharacterMotor` gains `turnSpeed` (degrees per second, `0` = instant) and turns `entity.node.rotation.y` toward the desired velocity; the turn math lives in a shared helper in `@waica/behaviors` for the next mover. No directional contract and no flips in 3D.
6. **Crossfade:** an `Animator` param `fade`, default `0.15` s, `0` = hard cut. No per-state override in this block.
7. **Loop and speed:** per-clip overrides on `Animator`, `clips: Record<gltfClipName, { loop?: boolean; speed?: number }>`, defaults loop `true` and speed `1`. The state machine stays space-agnostic.
8. **Art:** a script generates a minimal rig (2 or 3 bones, clips idle/walk/jump) as the deterministic fixture for unit tests and the e2e, and a real CC0 character (KayKit or Quaternius, with `ATTRIBUTION.md`) is the Player of `examples/smoke-3d`, so the pipeline is proven on a third-party glb.
9. **A `character` role in `@waica/behaviors`:** the idle/walk/jump/fall graph; the role reads `RigidBody` (`grounded`, velocity) and emits `move/stop/rise/fall/land` like `player-states.ts`; `Animator` plays what the state machine chooses. Block 5 reuses it.

## Handoff

**Topic and scope.** Play the clips of a glTF in scenes with `render.space: '3d'`, extract the `play(clip)` contract from `StateMachine` so it talks to whatever plays clips without importing `AnimatedSprite`, give the 3D character a facing by rotation, and close the loop with a 3D role, an animated character in the smoke and e2e verification. One spec. Camera, 3D editor and the archetype stay out.

**Confirmed decisions.** The nine above; the spec takes them as confirmed and does not re-ask them.

**Constraints and non-goals**
- No follow, orbit or zoom camera and no camera-relative input (block 5). No editable 3D viewport (block 4): `Animator`'s params reach the inspector through the generic param rows. No archetype package.
- No retargeting, root motion, blend trees, animation layers, IK or morph-target authoring (a clip that carries morph targets plays through the mixer as is).
- 2D is untouched except for what is additive: the extracted interface and `clip:end`. 2D clips and `ClipDef` do not change.
- No new dependency (`AnimationMixer` and `SkeletonUtils` ship with three). Nothing new in `game.ts`. The fixed step (ADR 0014) and the Component Update Schedule do not change.

**Explicit assumptions** (the spec lists them as `[ASSUMED]` inferences)
- `WebGPURenderer` draws `SkinnedMesh` with the `MeshStandardMaterial` that `GLTFLoader` builds [inference: the e2e already draws `tree.glb` with that material; three ships a `webgpu_skinning` example].
- `AnimationMixer.update(1/60)` is deterministic: a hash of bone poses after N steps is testable like the physics position hash.
- A `play()` requested before the model has loaded is remembered and applied when the handle settles; `initialClip` likewise. A missing clip name warns once, like the state machine's missing-clip warning.
- Clip names match the glTF names exactly, plus the per-state `clip` override that already exists (`idle → "Idle"`); the spec decides whether a case-insensitive fallback exists.
- `validate_project` extends `missing-clip` to `Animator` by reading the clip names from the glb's JSON chunk; an `Animator` without a `Model`, or a model without clips, is a finding plus one runtime warning. `Animator` in a 2D scene is a `component-space-mismatch` through `static space`.
- Runtime Snapshot: `Animator` exposes `current`, the clip time and whether it is playing (`inspectState`); `CharacterMotor` exposes nothing new (the yaw is already the entity's `rotation`).
- One bench scenario, `skinned-characters-{N}`, with deterministic counters like `animated-sprites`.
- A CC0 pack exists as glb with idle/walk/run/jump clips, 1 to 3 MB [inference: KayKit and Quaternius catalogs; verify license, size and clip names in the spec]; its clips animate in place.
- Minor bump with a migration note, decided at the end as 0.26.0 was.

**Risks and deliberately deferred questions**
- **#151:** CI's Linux WebGPU frame is blank; the animation pixel assertions run only where the frame draws, like the rest of the 3D leg. Snapshot and pose assertions run on both backends.
- A box `Collider` on a yawing entity does not follow the yaw (the collider takes its rotation when the body is created); the character's capsule is symmetric and unaffected. Document it.
- `state/state-machine.ts` (295 lines) grows with the interface and `clip:end`; the spec decides whether to split the module.
- Per-entity cost of `SkeletonUtils.clone` plus one mixer at high N: the bench measures it, this block does not solve it.
- The CC0 glb adds weight to the repository; `examples/smoke-3d` is private and not published, so the packages do not carry it. The e2e copies it into a demo Project like `tree.glb`.
