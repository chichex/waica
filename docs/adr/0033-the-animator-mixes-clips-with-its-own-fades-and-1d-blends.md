# The Animator mixes clips with its own fades and 1D blends

ADR 0029 gave the `Animator` one crossfade per component (`fade`, through three's `crossFadeTo`) and left a finer fade and blending for later. Issue #205 adds both, without touching the Clip Target contract, the `StateMachine` or `CHARACTER_STATE_GRAPH`: the machine still calls `play(name)`, and everything new lives on the Animator.

**Per-clip fade.** `clips[name].fade` is the fade *into* that clip, in seconds; without it, `fade` applies, and 0 cuts. A `fade` that is negative or not a finite number warns once and the global one applies (`validate_project` reports `invalid-clip-fade`). Fading per state or per transition was rejected: it would put playback on the machine, which stays space-agnostic.

**Fades from the current weight.** The Animator schedules its own fades (`AnimatorMix`) instead of three's `crossFadeTo`/`fadeOut`, whose fade-out always starts at weight 1, so a fade interrupted half way jumped. Entering a clip moves it from the weight it has to 1 over its fade, and every other sounding clip from its own current weight to 0 over that same fade: no leaving clip ever gains weight, and the weights add up to 1 on every step. A clip that reaches 0 stops. A clip asked for again while it still carries weight continues from its time and rises from its weight; a silent clip, or a finished one-shot, restarts at 0 (ADR 0029's restart of a finished one-shot holds). The first `play` cuts, as before.

**1D blends.** The `blends` prop, `blends.<Name> = { param, points: [{ clip, at }], smoothing }`, makes each entry a virtual clip: its name joins `clipNames` after the file's clips, `play("<Name>")` sounds it, a state plays it with `clip: "<Name>"`, `current` is its name, and it never finishes (`clipFinished` stays false, so `clip:end` never fires for it and `validate_project` warns `clip-end-on-looping-clip`). Its points mix by a named parameter: `animator.setParam(name, value)` sets a target, the value approaches it by a first-order lag (`v += (target − v)·min(1, dt/smoothing)` per Simulation Step, snapping within 1e-4; plain arithmetic, no `Math.exp`, so the value is the same on every platform), and the two points around the value weigh linearly, the end points alone past either end. A parameter nobody wrote is 0, a `setParam` before the file loads is kept, and a value that is not finite is ignored with one warning. `smoothing` defaults to 0.15 s; a parameter read by two blends takes the first one's. The `character` and `enemy` roles write `speed`, the planar speed of their body.

**Phase.** A blend's clips share one normalized phase φ: each step adds `dt / Σ wᵢ·(durationᵢ / speedᵢ)`, the cycle interpolated by the points' weights (a clip's `speed` override scales its duration first), and each clip sits at φ × its own duration, so the feet of walk and run land together (KayKit's `Walking_A` and `Running_A` both start on the left foot, one cycle each). Each point plays its own action over a copy of the clip that shares its tracks, which the mixer never advances (time scale 0): a clip can sound alone and inside a blend at once, each keeping its own time and weight. `time` reports φ × the interpolated cycle.

**Exposure and edges.** `inspect_runtime` keeps `{ loaded, current, time, playing, poseHash }` and adds `weights` (each glb clip's effective weight, a blend's clips multiplied by the blend's weight, only those above 0, the leaving ones included) and `params` (the smoothed values). A blend named like a clip of the file loses to the clip; a point whose clip the file lacks, or that names another blend, is skipped; a blend with no point left plays like an unknown clip; each warns once per entity and none throws. The pose stays a function of the steps taken: the pinned 110-step walk digest of ADR 0029 does not change, and two Games mixing the same script end with bit-identical bones.

Out of this decision: a 2D directional blend and a strafe mode (a later issue), masked layers, additive clips, root motion (#207), retargeting (#206), IK, blends in 2D (`AnimatedSprite`) and nested blends. Rejected: `crossFadeTo` with `warp` (it still fades out from 1), syncing a blend to its heaviest clip (the cycle would jump as weights cross), and one action per clip shared by the blends (a clip sounding alone and in a blend would fight over one time and one weight).
