# The editor edits 3D scenes through its own view camera

The editor no longer opens a 3D scene read-only (issue #173). In edit mode the viewport's Game draws, picks and projects through the **Editor Camera**: an editor-owned `THREE.PerspectiveCamera` set with `game.cameraRig.setViewCamera(camera)`. While one is set over a 3D scene, `game.camera` returns it, so the frame, the Pointer and `game.worldToScreen` follow it through the one seam they already read; `game.cameraRig.sceneCamera` keeps returning the camera the scene JSON places, and `setSceneCamera` keeps updating it. `setViewCamera(null)` restores the scene camera, and a 2D scene ignores the call with one warning. The Editor Camera starts at the scene camera's pose, moves only by navigation (three's `OrbitControls`, damping off: middle or Alt+left orbits, right or Shift+middle pans, the wheel zooms; arrows, Shift+arrows, `+` and `-` step on the focused viewport), is remembered per scene in the workspace entry, and never writes the scene's `camera` block. Play rebuilds the Game with no view camera and draws through the scene camera, as before.

Picking goes through the engine's own raycast, now public: `raycastPick(camera, at, entities, extra?)` tests every live Model root (a glTF's nested meshes resolve to the entity that owns it, a posed skinned mesh where its skeleton put it) and the `extra` targets a host adds, nearest hit first. The editor's extra targets are billboard icons of constant screen size for every Sun, PointLight and entity with no Model, and one for the scene camera, whose click opens the camera inspector. Transforms are edited with three's `TransformControls` on a pivot that stands for the selection (the entity's own pose, or the center of a group's positions); a released drag commits every dragged entity's position, rotation (Euler degrees XYZ) and scale, rounded to 0.001, as one undo step. Ctrl snaps the drag to per-user steps.

## Considered Options

Overriding only the frame's draw with a separate camera, and passing that camera to picking on its own, was rejected: the Pointer, `worldToScreen`, Anchored Pieces and spatial audio all read `game.camera`, so one override at that seam keeps every consumer consistent, and `game.ts` stays where it was against its line cap. A raycaster of the editor's own, duplicating how the engine resolves a hit to its entity, was rejected for the public `raycastPick` with extra targets: one rule for what a click hits, tested once. HTML icons placed with `worldToScreen` were rejected for `THREE.Sprite` billboards, which the same raycast hits. A hand-rolled gizmo, as a fallback in case `TransformControls` misdrew under `WebGPURenderer`, was not written: `TransformControls` is plain meshes with basic materials, and the e2e checks that it draws and drags on the WebGL2 backend. Its drawing on WebGPU is not verified by the e2e (CI's Linux WebGPU draws a blank frame, issue #151), so that backend relies on the renderer converting those meshes like any other.

## Consequences

ADR 0027's read-only clause is superseded: the editor picks, transforms, drops prefabs on, frames and grids a 3D scene, and draws helpers (the scene camera's frustum, each Sun's direction, each PointLight's range, each Collider's shape) and icons in edit mode only. A game script that read `game.camera` during an edit-mode `onUpdate` would see the Editor Camera, but the editor's edit-mode Game does not simulate, so no game code runs there; Play never has a view camera. The editor depends on `three` directly, at the engine's range, to import `OrbitControls` and `TransformControls` from `three/addons/controls/`; no new package enters the lockfile. The Animator's clip fields list the glb's clips, read from the file's JSON chunk by the engine's `glbClipNames(bytes)`, which the MCP's clip validation reads `.glb` files through too. The editor's browser e2e drives a 3D project through a DEV-only `window.__waicaEditor` hook that a production build drops. Marquee selection in 3D, snapping to other objects, pivot modes other than the selection center and editing a Collider's shape with handles are later work.
