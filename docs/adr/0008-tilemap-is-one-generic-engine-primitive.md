# The tilemap is one generic engine primitive, not a per-archetype map system

Maps become a first-class engine primitive: a single component owning a square lattice of cells in logical coordinates, rather than one entity per tile. It is one primitive for every archetype: under an isometric scene projection (ADR-0009) the same square cells draw as 2:1 diamonds, so the diamond is a property of the scene's projection, not a lattice parameter of the component — one source of truth. The isometric archetype introduces it; topdown opts in at the same time (registering it, not migrating its existing tile entities); platformer keeps tiles-as-entities until it opts in. Rejected alternatives: an iso-only tilemap (smaller, but it leaves two map systems coexisting with no convergence plan); a `lattice: 'square' | 'diamond'` parameter on the component (the literal first wording of this decision, dropped once the projection seam made it redundant and contradictory — a diamond lattice in logical space has no meaning); and migrating topdown's existing maps in the same effort (immediate convergence at the cost of regression risk on a published archetype).
