# The tilemap is one generic engine primitive, not a per-archetype map system

Maps become a first-class engine primitive: a single component owning a lattice of cells whose grid type is a parameter — square or diamond — rather than one entity per tile. The isometric archetype introduces it and is its first consumer; platformer and topdown keep tiles-as-entities until a separate, optional migration. The engine therefore ships a square mode no stock archetype exercises yet: that asymmetry is deliberate — the square lattice is the degenerate case that keeps the abstraction honest against the two existing tile-based archetypes, without risking a regression on published ones. Rejected alternatives: an iso-only tilemap (smaller, but it leaves two map systems coexisting with no convergence plan), and migrating topdown in the same effort (immediate convergence at the cost of regression risk on a published archetype).
