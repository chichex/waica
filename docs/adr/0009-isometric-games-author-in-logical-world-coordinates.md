# Isometric games author in logical world coordinates; the engine projects at render time

An isometric scene's entities live on a logical square grid — isotropic speeds, axis-aligned collision, scene JSON storing logical coords — and a render-time seam projects logical position into the node's screen position each frame (the same shape as the y-sort pass), decoupling `Entity.position` from `node.position` for these scenes. Depth needs no new sort mode: projected screen Y is equivalent to logical x+y ordering, so the existing opt-in y-sort stands. Rejected alternative: authoring directly in screen space, which kept the engine untouched but was refuted by the comparative spike (`spike/iso-projection`, `examples/iso-spike/REPORT.md`): the per-axis solver dead-stops against diagonal Solid faces and deadlocks in the concave sawtooth between adjacent diamond Solids, movement axes never align with the map (players drift off the ground diamond), and fixing that would mean teaching the solver slide-along-normal responses — engine work comparable to the seam, spent fighting the projection instead of removing it.
