# The game reaches its host platform through a replaceable seam, and the desktop shell serves it over `app://`

A Game asks its host to quit, to go fullscreen and to record achievements through `GameOptions.platform: PlatformBackend` (issue #200), the seam ADR 0013 describes for audio. Absent, the Game picks the desktop backend when `window.waicaDesktop` exists and the web backend (`WebPlatformBackend`) otherwise, so an existing Project's `main.ts` gets the desktop APIs without a change. On the web `game.canQuit` is `false` and `quit()` does nothing, fullscreen is the browser's Fullscreen API, and `game.achievements.available` is `false`, with every call a no-op. The store-agnostic `achievements` (`unlock`, `setStat`, `getStat`, `available`) is what a later Epic or GOG backend would also implement.

`waica export desktop` packages the Project's own `vite build` into an Electron app. Its main process registers `app` as a privileged scheme (`standard`, `secure`, `supportFetchAPI`, `stream`) and serves `dist/` through `protocol.handle`, so the page is a secure context (WebGPU asks for one), the build keeps Vite's default `base: '/'`, and `'/waica.params.json'` and Rapier's lazy chunk resolve against `dist/` as they do on a web server. A path outside `dist/`, including an encoded `%2e%2e`, answers 404.

The page never touches Node. The window runs with `contextIsolation: true` and `nodeIntegration: false`, and a sandboxed preload exposes `window.waicaDesktop` (`DesktopBridge`) through `contextBridge`: `quit`, `setFullscreen`, `isFullscreen` and, when the export includes Steam, `achievements`. Each call is an IPC message that the main process answers; the main process alone loads `steamworks.js`, and it forwards only ids the Project declares in `desktop.steam`.

## Considered Options

Loading `dist/index.html` from `file://` was rejected: it is not a secure context, and every absolute URL a Vite build emits (`/assets/…`, `/waica.params.json`) would resolve against the filesystem root, so the template would need `base: './'` and a relative params URL. A local HTTP server inside the app was rejected because it opens a port on the player's machine for no gain over a custom scheme. Exposing Electron or Node to the page (`nodeIntegration`) was rejected: a game's own code, and anything it loads, would get the filesystem. Passing the platform explicitly from the template's `main.ts` was rejected because every Project generated before this change would then need an edit to quit or go fullscreen.

## Consequences

`GameOptions.platform`, `PlatformBackend`, `PlatformAchievements`, `WebPlatformBackend` and `DesktopBridge` are public API of the engine. The shell's preload and the engine's desktop backend agree on the `DesktopBridge` shape across two packages; the engine accepts a `window.waicaDesktop` only when it has that shape and falls back to the web backend otherwise. A fullscreen request on the web resolves even when the browser refuses it, so a game reads `isFullscreen()` rather than trusting the promise.
